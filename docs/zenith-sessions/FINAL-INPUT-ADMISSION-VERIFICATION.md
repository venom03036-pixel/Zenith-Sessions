## Resource cost, limitations and next integration

This repair adds one fresh final target inspection per admitted bound event, plus fresh virtual-desktop metrics for bound absolute movement. Earlier stopped/paused states can return before a target query; pointer preparation may also inspect bounds. Reused filter scratch sets and one options snapshot per context avoid a new per-input context map, capture loop, timer or unbounded task queue. No claim of improved throughput, UI latency or client capacity follows from these checks.

**Final pre-send validation is not atomic target delivery.** Windows global input has no per-window reservation; a state change after admission remains possible, and native acceptance is not receiver consumption. Actual-context binding does not partition the Win32 player's global held-input sets. The existing foreground executor still requires exclusive operation ownership.

Source review confirmed that sharing one player across editor and Auto Clicker is not an atomic lease. UI booleans and InputModeGate do not enforce that ownership, and Auto Clicker's caught release failure can clear activity flags while native holds remain. Before production execution IPC, the next integration must acquire one nonqueued operation lease before asynchronous startup, retain it through pause/actual completion/cleanup, quarantine failed cleanup and join real shutdown work. Recording and pickers must participate, and stale cleanup must not stop a replacement operation. Future targeted groups must reserve against legacy desktop activity while separately leasing each recipient; independent runs must not attach to the same foreground player.

Production control IPC, target-specific images/conditions and complete macro compatibility remain unfinished.
