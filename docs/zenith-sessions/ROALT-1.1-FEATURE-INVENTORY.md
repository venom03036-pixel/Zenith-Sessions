# RoALT 1.1 and Zenith feature inventory

The reference is [RoALT 1.1.0 at `d16b3e2`](https://github.com/inspectsoftware/RoALT/tree/d16b3e277ce24859a5159354a6f289891b09fe2f). The local RoALT 0.4 source is historical. The inventory reads the 1.1 README, UI routes, settings registry, performance entries and command surface. Zenith retains its own design and implementation. Legacy coverage refers to the [Zenith requirements ledger](REQUIREMENTS-LEDGER.md), which separates source and offline evidence from real client trials.

“Legacy” means the previous Zenith checkout has the feature or a documented partial path. “Pending” means the rebuild has no accepted equivalent yet. “Excluded” means the product boundary is intentional. Proof and exact launch trial steps are in the [Rust probe record](RUST-LAUNCH-PROBE.md).

## Accounts and vault

- **Official sign-in, check one or all, renew sign-in, cancel login.** The Rust preview opens an isolated first-party sign-in, checks the completed landing and identity, saves with Windows encryption, selects the saved profile, and waits for window closure before the next sign-in. It retries temporary verification failures within a fixed limit and shows which account was saved. Verified replacement sign-ins persist during private profile reads and launch preparation. Synthetic checks passed. Browser auto-save and actual Roblox rotation need attended trials. Bulk checks remain pending. [Trial steps](RUST-DESKTOP-PREVIEW.md#preview-125-account-selection-and-sign-in-closure)
- **Account table, add/remove, reorder, aliases, notes, groups, favorites, search, filters, selection.** The Rust preview uses the Make account table with saved identities, search, single-account selection and removal. The protected legacy import preserves notes, aliases, groups, priorities and favorite flags and shows matched records in the inspector. Editing, reorder, favorites filtering and broader filters remain pending.
- **Avatars and presence.** Rust has anonymous Roblox headshots keyed to the saved player identity. The account cell opens the matching profile inspector. It retries pending thumbnails and bypasses a cached failure when retrying an image, with initials when a thumbnail is unavailable. The six-account browser fixture and anonymous public smoke check passed. Live presence is pending.
- **Robux, membership, social counts, friends and follower lists, two-step status, inventory, limiteds and account value.** Rust account details include verified-account Robux and paginated friends, plus public profile details and public favorite games. Synthetic profile reads and public endpoints passed checks. Real-account detail retrieval needs an attended check. Membership, wider social counts and follower lists, two-step status, inventory, limiteds and valuation are pending.
- **Main-account protection (`protectMain`, `acct.main`).** Zenith can add an explicit account protection flag for bulk actions. Pending. Test Select All and group launches with the protected account present.
- **Per-account overrides (`acct.fullQuality`, `acct.fpsCap`, `acct.launchArgs`, `acct.customFlags`, `acct.bringBack`, `acct.discordMuted`).** Legacy has validated extra arguments and parts of resource control and alerting. Rust override precedence, allowed arguments, restoration, retry settings and alert routing are pending. Client flags remain subject to the performance boundaries below.
- **DPAPI, password, recovery, lock (`encryption`, `masterPassword`, `recoveryCode`, `autoLock`).** The Rust preview persists per-account DPAPI bundles in a separate library and rejects a mismatched identity. Rotation preserves the existing record format and compares the encrypted record before committing. The migration exports metadata from a password-protected vault while keeping its sign-ins in the original vault. Password-protected sign-in migration, vault locking and recovery remain pending.
- **Cookie paste/import, account-manager import, reveal, copy, plaintext export and cleanup (`clipboard`).** Raw credential reveal, clipboard transfer and plaintext export are excluded. Zenith will use the official sign-in flow and its own encrypted migration. Third-party account-manager import has no accepted format or trusted migration flow.
- **Encrypted backup and restore (`backup`).** Legacy has a protected portable format. The Rust rebuild imports a current-user protected legacy snapshot with metadata and eligible sign-ins. Synthetic tests cover preservation of the original fixture, password protection and retry. The [migration and rollback guide](RUST-DESKTOP-PREVIEW.md#preview-107-legacy-workspace-migration) uses the original WPF library for rollback. Portable Rust backup/export and restore are pending.

## Play, servers and browsing

- **Account picker, place ID/game link, exact public job, saved target, follow a player and join a friend.** The Rust console probe proved the saved-account and public-place path. The desktop preview accepts a place ID, public game link, search result or imported favorite and can pin one exact public server. The native envelope and wrong-server rejection passed controlled tests. Desktop launch and exact arrival still need the attended [preview trial](RUST-DESKTOP-PREVIEW.md). Favorite editing, follow and friend joins are pending.
- **Public server sort, pagination, occupancy, ping, server FPS and last visited.** The Rust preview offers both player-count orders, an optional full-server view, and forward and backward paging. Rows show reported occupancy, ping and server FPS when available. Browsing preserves an explicitly selected destination, and Roblox assigns seats at join time. Server history remains pending. [Browser and trial evidence](RUST-DESKTOP-PREVIEW.md#preview-128-public-server-browser)
- **Private link/share-link resolution, private list, same-server join, split by private/random/closest.** Rust saves a protected local invite list with rename and removal. Direct links and Server share links have a separate single-account native request. Modern share links resolve using the selected verified account. An invalid private target cannot take the public route. Loopback and protected-storage tests passed. Provider-listed private servers, multi-account routing, and actual private arrival remain pending. [Trial steps](RUST-DESKTOP-PREVIEW.md#preview-121-protected-private-server-invites)
- **Create/buy, renew, permissions and private settings.** Purchases, renewals and access edits are excluded from current scope. Zenith's private-server labels apply to its saved invites. Roblox-side renaming remains pending.
- **Game media and details.** Rust displays the selected experience's public details, icon, and up to six thumbnails in Sessions. The requested place and pinned public server stay selected. Live public endpoint and controlled UI evidence are recorded in [Preview 1.20](RUST-DESKTOP-PREVIEW.md#preview-120-public-game-details-and-artwork). The reference's likes, favorite counts, passes, prices and badges remain pending.
- **Signed-in Browse, account switch, back/forward/reload, home, games, marketplace, avatar, friends, popular, playtime, game/player details and Play capture.** No accepted Rust equivalent. Separate trusted local UI from isolated Roblox content before implementing authenticated Browse. Public game search and direct launch are the first substitutes. User-scoped playtime can come from Zenith’s tracked session history once available.
- **Queue, launch delay, cancel, progress, same-server preference, several accounts per server (`launchDelay`, `launchArgs`, `launch.windowLayout`, `launch.fpsCap`).** Rust has individual requests, per-account progress, cancellation, and a serialized start gate with a fixed 20-second stabilization interval for a pair. Controlled tests cover duplicate identity, stale attempts and a stopped first client during second-account preparation. Persistent queueing, configurable delay, batch preferences and recovery remain pending.
- **Multi-instance, takeover and shared login protection (`multi`, `protectLogin`).** The desktop and command-line pair trial can reserve an unused compatibility name. An existing object remains outside Zenith's ownership. Exact process-birth and synthetic Windows object checks passed. Live coexistence awaits the two designated saved sign-ins and the [attended pair procedure](RUST-DESKTOP-PREVIEW.md#preview-104-and-the-attended-two-account-trial). Takeover and shared login file changes still require separate implementation and evidence.
- **Disconnect rejoin, crash/hang restart and retry breaker (`autoRejoin`, `autoRestart`, `breaker`).** Rust persists a bounded launch journal, checks exact process identity after restart, and holds admission for uncertain starts. A public launch can opt in to two automatic replacements after a recognized fatal exit from an owned client with confirmed arrival. The same requested place and public job are retained, with 8- and 16-second delays and normal admission. Controlled tests passed. Live recovery, adoption, disconnect rejoin, and hang restart remain pending. [Fatal-exit trial](RUST-DESKTOP-PREVIEW.md#preview-122-fatal-exit-recovery)
- **Roblox install/update selection and auto-update (`client`, `autoUpdate`).** The Rust probe resolves the current registered standard player and verifies the publisher. Its live trial exposed a stale executable updating out of process. Rust still needs a production update handoff policy, recovery and diagnostics. Other bootstrapper adapters and a built-in installer remain follow-up work.

## Windows, monitoring and performance

- **Preview cards, account tabs/rail, reorder, resize cards and focus.** Legacy has an owned-window view and bounded previews. Rust needs verified ownership, one bounded preview service, visible-tile priority, and recapture after occlusion. UI cards come from Zenith’s design.
- **Focus, minimize, restore, orderly close, force stop and clear ended.** The preview exposes Focus, Minimize and Restore for confirmed windows. Sessions can request normal close on a single owned window and wait for exact process exit. Per-client force stop asks for confirmation and rejects stale attempts. Bulk force stop remains available. Native fixture and browser tests passed. Attended desktop tests, bulk visibility changes and history clearing remain pending. [Close trial](RUST-DESKTOP-PREVIEW.md#preview-127-normal-close-and-exact-force-stop)
- **Desktop layouts, tile, stack, fit, shrink and move.** The Rust Windows page evenly tiles confirmed, restored owned clients on Zenith's monitor. The command checks the work area, scale, process birth and each window's minimum size, then reports observed bounds. A native cross-process fixture and planner tests passed. Attended Roblox and mixed-DPI placement, additional arrangement controls, and automatic layouts remain pending. [Trial steps](RUST-DESKTOP-PREVIEW.md#preview-106-desktop-windows)
- **CPU, memory, commit, GPU/VRAM, I/O, uptime, charts and totals.** The Rust Performance page measures CPU, distinct memory counters, I/O transfer rates and uptime for confirmed, currently owned processes. Synthetic sampling and a native Windows child fixture passed. Launch admission still uses physical/commit headroom and a bounded single-attempt override. GPU/VRAM, histories, totals, and measured Roblox benchmarks remain pending. [Trial steps](RUST-DESKTOP-PREVIEW.md#preview-109-account-refresh-and-client-performance)
- **Max alts, Balanced, defaults, and machine measurement (`presets`, `maxAlts`, `balanced`, `defaults`, `bench`).** Zenith needs reversible presets and review based on measured workloads. Rust has no validated speed or capacity comparison. First prove one and two accounts before scaling to 4, 8 and 16 and recording readiness, UI response and overhead.
- **FPS cap and graphics (`fpsCap`, `lowGraphics`, `lighterRendering`, `msaa`, `texture`, `renderMode`, `graySky`, `noGrass`, `lowestFrm`, `pauseVoxelizer`, `customFlags`).** Legacy performance paths have partial tests. Rust has no qualified client setting path. Supported settings need before/after measurement and restoration, including update and crash cases. Arbitrary rendering flags and unsupported settings are unavailable until there is evidence that the current player accepts them safely.
- **Minimize, tiny windows and mute (`minimize`, `tinyOnLaunch`, `mute`).** Rust can explicitly minimize one confirmed owned window. Automatic minimize at launch, tiny sizing and per-client mute remain pending. Sizing and audio controls need verified targets and supported minimums.
- **Adaptive foreground/background limits, CPU cap, affinity, scheduled trim, memory throttle and restart (`adaptive`, `adaptiveBg`, `fairCap`, `spread`, `trim`, `memThrottle`, `memThrottleCpu`, `memRestart`).** Rust supports opt-in Below normal priority and a separate Windows efficiency request for confirmed owned clients. Both controls have native readback and a same-process restore action. Adaptive policies, CPU caps, affinity, trim, memory throttling and live performance benefit remain pending. [Efficiency trial](RUST-DESKTOP-PREVIEW.md#preview-124-windows-efficiency-for-an-owned-client)
- **Preview FPS, network cap and performance sharing (`previewFps`, `bandwidth`, `share`).** Rust needs a capped frame-rate setting, supported Windows QoS, and a metadata-only profile format. Benchmarks must record preview configuration. Share profiles must exclude credentials and arbitrary launch commands.

## Workspace, safety and tools

- **Keep Awake and per-client interval (`antiAfk`, `antiAfkEvery`, `client.antiAfk`).** Legacy policy and synthetic input checks exist. Rust is pending. Real background behavior requires an explicit supported input path, verified ownership and opt-in attended testing.
- **Panic and close grace (`panic`, `closeGrace`).** Rust has a persistent Panic button and a native Ctrl+Shift+P worker. Both revoke launch permits, stop currently owned clients, and hold fresh starts until explicit resume. Per-client normal close has a fixed five-second grace period. Synthetic browser, ticket, and Windows shortcut tests passed. Attended Roblox and physical-key tests, configurable and bulk grace policies, and macro-input integration remain pending. [Trial steps](RUST-DESKTOP-PREVIEW.md#preview-111-emergency-stop)
- **Scheduled shutdown (`shutdown`).** Legacy has the opt-in flow. Rust is pending. Exercise cancellation and failure in a disposable Windows environment.
- **Theme, accent, wallpaper, dimming, density, layout, language, sound, motion, tray and splash (`theme`, `accent`, `background`, `backgroundDim`, `density`, `tabLayout`, `language`, `sounds`, `motion`, `closeToTray`, `skipSplash`).** The preview renders the Make shell's navigation and supports its six named themes plus Follow Windows, with a saved appearance choice. Wallpaper, standalone accent and density controls, layout preferences, localization, sounds, tray behavior and splash remain pending.
- **Keyboard shortcuts.** The reference lists Overview, Accounts, Play, Servers, Settings, Monitor, Discord, Debug and Performance navigation. It also lists Add account, Find, Select All, Check sign-ins, Remove, Launch, Refresh, Lock, Close and Help. Zenith should bind each action to its working control when the corresponding page lands. The Rust diagnostics window has keyboard-accessible Refresh and native Close. The wider shortcut map and conflict handling are pending.
- **Purchase lock and public networks (`lockPurchases`, `publicNetworks`).** Zenith has no purchasing workflow. Legacy has a public-network hold and lock policy. Rust network classification and launch admission wiring are pending.
- **Data directory, cache lifetime, old logs, WebView reset (`dataFolder`, `cache`, `cleanLogs`, `browserData`).** Show the app’s own data path and bounded cache/log policy. Moving the data directory is excluded. Rust retention and scoped browser cleanup are pending, with rollback and credential preservation checks.
- **Updates, version and support (`selfUpdate`, `version`, `support`).** Legacy has signed staging and installer work. Rust needs package identity, verification, release notes and rollback. RoALT branding, donation links and community support links are excluded.
- **Reference online counter and Rolimons (`onlineCount`, `rolimons`).** The RoALT counter has no Zenith equivalent. Third-party item valuations are optional pending work separate from the session core.
- **News, Debug, crash detail, server visits and diagnostic export.** Rust exports a local allowlisted support report with the build hash, memory admission, typed launch failures, native exit status when observed, recovery counts, and Panic status. Browser and Windows file tests cover the export. Legacy has scoped News and persistent client history. Deeper crash classification, history, and unread feeds remain pending. [Support report](RUST-DESKTOP-PREVIEW.md#preview-123-local-support-report)
- **Discord presence, webhook and event selection.** Legacy has opt-in settings and controlled checks. Rust is pending. Any real webhook or presence trial requires separate destination authorization.
- **Macro catalog, assignment and playback.** Rust Automation reads bounded saved-macro metadata from the Personal catalog pipe and stores local assignment references in an encrypted overlay. Target review supports accounts, imported groups, and imported bundles. The paired desktop builds expose foreground Start, Pause, Resume, and Stop for one owned client using the existing engine's bounded key-and-delay scope. Controlled Windows and browser checks passed. Live playback, wider macro action support and assignment precedence across overlapping scopes remain pending. [Trial steps](RUST-DESKTOP-PREVIEW.md#preview-118-paired-foreground-playback)
