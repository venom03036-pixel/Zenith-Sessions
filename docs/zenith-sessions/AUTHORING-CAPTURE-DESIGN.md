# Shared asynchronous authoring capture — cycle 0.47

Previous cycle 0.46 is verified progress: its immutable evidence and independent audit cover shared operation ownership and 120 new controlled cases. It did not finish the companion. This cycle removes the remaining independent image-template capture and repairs the related authoring lifetime; it does not add a Roblox provider or claim native freshness/performance.

## Current evidence and required behavior

`ImageSourceDialog.CaptureRegionToTemplate` creates a GDI service and synchronously waits on the UI thread. Capture Target Image drops embedded bytes in its pending condition. Region-presence sampling synchronously waits for a whole frame and can substitute a default swatch on failure. Color picker directly samples GDI rather than using the shared source. Visual Wait hides a modal dialog and starts an untracked async capture; hiding can end ShowDialog before that work ends. SharedCaptureService cancellation may complete a request task before an accepted source acquisition ends. These are source findings; no real-desktop failure or speed measurement is inferred.

Preserve all existing Add Image, image-kind conversion, Apply, capture/replace, import, control-flow, AutoClick, source-region placement and encrypted-save behavior. Existing synchronous TryCommit/selection/save/export contracts and injected synchronous prompt delegates remain usable. F10's production callsite consumes the same detached encoded template and actual physical source region, skipping search placement; preserve its existing raw-frame helper for compatibility callers. This removes its separate WPF BGRA assumption and frame-array/PNG roundtrip. Do not disable implicit capture, return path-only synthetic captures, introduce a second capture owner, or borrow Playback/Recording leases for authoring.

## Incremental contract

Use the existing Editor operation lease and shared IScreenCaptureService/IImageEncoder. One narrow non-window modal preparation bridge preserves the synchronous WPF commit boundary while one actual preparation task runs asynchronously. It uses a DispatcherFrame only to pump the existing UI, with no new HWND, timer, sleep, spin or blocking wait on an unfinished Task. A tracked observer exits that frame on actual completion. Dispatcher shutdown/early frame exit cancels publication and signals the exact lease; actual preparation, frame disposal, privacy restoration and lease retirement remain tracked/joined by Editor shutdown. No exit-resistant loop or synchronous cross-dispatcher call.

Separate UI source choice, region selection and placement from preparation. The source chooser is fully closed before any pixels are acquired. ImageSourceDialog becomes source-intent UI; capture, encoding, bounded file read/decode, validation and output ownership belong to the application/controller. Keep screen privacy in the actual asynchronous owner, not an outer using that an early modal exit can unwind. Marshal privacy operations to the actual App dispatcher and join restoration. Capture/placement cancel closes only the exact owned managed window through its dispatcher; native OpenFileDialog may still require dismissal and must not be advertised as instantly cancellable.

A small application-layer AuthoringImagePreparer borrows the existing capture/encoder and exact interactive parent. It provides capture-template, bounded import, exact-pixel and bounded Visual Wait sampling. It owns and disposes each returned frame. Reject invalid physical regions before capture, cap ordinary template edges at 4096 and encoded bytes at 32 MiB, and apply the existing Visual Wait 512-edge cap. Require the returned frame's geometry/origin to match the requested physical surface; reject clipping or invalid formats rather than silently translating coordinates. Preserve native pixel/color semantics, including negative coordinates and valid black pixels. Use the existing encoder/decoder, no full-frame ToArray or readable temporary PNG.

Preserve the existing one-pixel minimum for imported images; the four-pixel minimum applies to a screen snip. A controlled harness against unchanged verified0.46 binaries reproduced swapped red/blue for declared RGBA frames in both PNG and JPEG. Correct the existing encoder's channel conversion, with a bounded native normalization only for RGBA PNG; BGRA/BGR retain their existing path. Validate declared format/row width before passing a pointer to OpenCV. This uses the existing dependency and is an actual synthetic-memory encode/decode correction, not desktop capture or a speed benchmark.

After accepted capture admission, call the shared request with CancellationToken.None and await its actual result; the shared service still owns its own shutdown token. Stop/caller cancellation fence publication and skip later preparation, but cannot be mistaken for evidence that native acquisition ended. Check the captured parent and stop generation before acquisition, after the actual frame and before publication. Frame/encoding/file work is bounded and off the UI thread. DXGI timestamps can be restamped on cached content, so retain chooser-close/settle ordering and make no stronger compositor-freshness claim.

Pin the document, step object/ID, draft and selection at authoring start; revalidate after every modal/pumped boundary. Old results cannot write into a replacement same-ID step, new macro or newer draft. Prevent reentrant commit/edit admission while a preparation is owned. Cancellation or stale Apply must not restore an old draft over a newer one. Captured bytes survive Capture Target Image → draft → Apply → actual encrypted store/reload; imports and control-flow captures use the same detached-byte contract.

Playback/recording currently commit drafts after acquiring their producer lease. A draft requiring image capture needs a fenced interactive preflight first, then actual retirement, identity/draft revalidation and fresh producer acquisition using the original stop generation. Do not weaken the no-borrow rule or let Panic during preflight turn into a delayed run. Existing custom shortcuts and operation state remain unchanged.

## Related authoring paths

Color hover uses the same parent-bound shared sampler: at most one actual request and one latest physical point/sequence, driven only by pointer events/completion and the existing 33 ms cadence. No independent timer or task per mouse move. Publish only the current sample. A click pins its actual point, closes the overlay, joins hover and makes a final exact 1×1 read while engine privacy remains active; never commit an older hover color. Actual overlay/compositor contamination and capture-exclusion behavior require later native validation.

Region presence samples its actual center through the shared 1×1 path. Invalid/unavailable sampling cannot become a successful fabricated red/black condition. Preserve editable existing defaults separately from a successful sample.

Visual Wait uses intent-only modal phases: close with a detached configuration/pick intent, acquire/sample outside the modal, and reopen only the current configuration with the result. Retain every draft field, search/mode/timeout/retry setting and final Create/Cancel semantics. No async-void capture worker or ShowDialog→Hide lifetime escape. Bound the sample DTO and keep actual frames out of the view.

## Rule 18 and Rule 20 review

One existing input/capture owner, one preparation task and one hover request/latest slot bound concurrency. No new packages, OS services, polling loops or capture backend. Per-prompt allocations are bounded; nothing is added to native input hot paths. No credentials, owner identities or real sessions are accessed. Error classification distinguishes ordinary completed work from explicit uncertain cleanup; failed restoration/retirement remains quarantined. Storage formats, SDK/player contracts, IDs/history and encrypted-document semantics remain unchanged.

Migration proceeds in the existing App/controllers and view adapters; Core/native SDK and installed Personal/Public/Linux products stay untouched. Independent design reviews identified the above constraints before product edits. Rollback uses matching development binaries without data migration. Root runs one sequential build/test/package lane after source freeze; agents must not build or mutate during that lane.

Acceptance uses controlled shared capture/encoder, real bounded decoder and isolated encrypted storage; actual dispatcher heartbeats during a gated preparation, Stop/close and early-frame-exit ownership, late frame disposal, stale document/step/draft rejection, exact color points/geometry/formats, bytes through all image workflows and saved reload, preserved Visual Wait drafts and no orphaned hover/capture. Compare the existing broad Core/Personal/manager/package regressions with the prior verified stage. Hidden WPF tests are not native focus/DPI/capture or measured user-desktop latency. Full execution IPC, real account/arrival/reconnect/background/broadcast, sixteen-client and competitive/release gates remain open.
