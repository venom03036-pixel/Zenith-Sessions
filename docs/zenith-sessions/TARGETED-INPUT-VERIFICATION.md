## Implemented and reviewed

[The design](TARGETED-INPUT-DESIGN.md) was independently reviewed before implementation. `TargetedInputCoordinator` is a platform-independent owner, separate from MacroSuite's existing foreground executor. It pins an immutable native target incarnation and purpose, permits one outstanding bounded batch per run, serializes transport submission, and keeps logical unfinished holds separate from submitted/possibly submitted holds. Paused and faulted runs retain their exclusive target lease. A future broadcaster cannot claim the same window while its macro still owns it.

Pause, Stop and Panic close admission and advance generations before waiting. Each event revalidates its target and checks admission at the transport boundary. Explicit resume restores only unfinished holds in order, at the latest possible pointer position. An uncertain submission retains cleanup ownership. Failed cleanup remains faulted and reserved until explicit retry; it never reports Ready. Disposal joins actual workers, including terminal tails whose target lease has been removed. Retries during active disposal reuse that finalization; a failed disposal can be explicitly repaired and retried afterward. No authentication, UI thread, network or save operation is required by the emergency signal.

Independent review and controlled regressions exposed and corrected transition-tail request loss, disposal missing a removed worker, cancellation during the final queued press, Pause rejection being mistaken for a fault, Pause downgrading an uncertainty fault, failed-disposal retry, and stale pointer coordinates after uncertain submission. Partial hold-restoration exceptions now return through cleanup. These are source/controller fixes; they are not reports of defects reproduced in Roblox.

`OwnedWindowMessageExecutor` now exercises the same owner instead of a separate direct input helper. Registration is restricted to this diagnostic process, with PID/start time, physical content bounds and immutable nonce. Actual receiver destruction retires that incarnation; a revoked live registration is unavailable rather than falsely called destroyed. It accepts only diagnostic F24 and left-button messages, with bounded registration/pending/receipt storage. Queued submission and cooperating-receiver sequence acknowledgments are distinct. There is no SendInput, focus-switching or external-window fallback. Capture readback now joins the real copy before releasing its borrowed frame, checking cancellation before/after instead of abandoning the surface on an observation timeout.

This component does not authorize an account or interpret a macro. MacroSuite foreground validation and player signatures are unchanged. No persistent schema, account grant, vault, installed edition, Public/Linux build or real Roblox session was altered. No dependency or third-party implementation was added.
