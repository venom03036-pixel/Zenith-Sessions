# Host input ownership — cycle0.46

Previous0.45 is verified progress, not a finished companion. The next prerequisite for production macro control is one authoritative Personal-host operation owner. Source review found startup gaps before activation returns, early stopped flags, unowned global releases, delayed pause acknowledgments and stale picker finalizers. One shared backend and InputModeGate alone do not provide exclusive operation lifetime.

## Incremental contract and integration

Add Core/Input `HostInputOperationArbiter`, `HostInputOperationLease`, `HostInputOperationKind` and a small immutable snapshot. One App-composed arbiter is injected into editor, Auto Clicker and picker/capture control. Old constructors gain trailing optional arguments for isolated callers; production must supply the same object. No service locator, new package, process service or second input/capture pipeline.

The synchronous nonqueued `TryAcquire(kind,out lease,out reason)` runs before any activation await, field edit or callback. An overload accepts an expected StopGeneration for future explicitly fenced commands. It returns fixed Busy/Quarantined/Closed feedback. A lease owns a stable ID, generation, fast `CanContinue`/`IsCurrent`/`OwnsCleanup`, a cached StopToken and an already-published actual completion task. Acquire invokes no callbacks. Caller startup/finalization tasks and cancellation owners are published before notifications can reenter.

`SignalStop` fences the shared generation and signals only the observed owner using tracked CancelAsync; `Close` closes admission first. Hook paths do not wait, invoke UI or release native inputs. Lease-specific SignalStop affects that captured lease only and cannot revoke a newer owner. `CompleteAsync(cleanupSucceeded)` is explicit, idempotent, joins tracked cancellation callbacks and runs only after actual producer/pause/cleanup work terminates. A failed cleanup retires the worker but retains a quarantined lease; no implicit Dispose releases authority. `DrainAsync` joins real lease/recovery completion after Close. An explicit `TryRecoverAsync(cleanup,ct)` may retry only a retired quarantined owner, retains ownership through actual cleanup and clears it only after successful fresh cleanup; cancellation/error preserves quarantine. No callback runs under the arbiter lock.

Keep UI flags as presentation/compatibility, not authority, and do not make a producer reject itself merely because the shared arbiter is Busy. Playback and recording acquire before activation, preserve destination/session identity, and retain the lease through accepted-input drain, journal/save finalization and actual cleanup. Stop joins actual finalization before a replacement hotkey run. Late recording watchers and finally blocks use their captured lease and cannot globally stop/reset a replacement. Metadata saves/catalog reads need no input lease.

Auto Clicker publishes one owned run before notifications, retains its lease while paused and joins its exact pause acknowledgement. Idle Stop/Shutdown must not release input or cancel another owner's picker. The manual click-speed tester emits no native input and stays lease-free, but its task/cancellation publication still needs reentrant-shutdown safety. Quarantine is surfaced truthfully and only deliberate recovery can clear it.

OneShotLocationPicker must use per-arm state, asynchronous ready/actual-thread-exited signals and captured cleanup. An old arm cannot tear down replacement fields. Finishing an ignored timed join is not a cleanup receipt; retain ownership until actual exit. Overlay setup/show failures must take the same cleanup path. Picker/capture routes reserve once; genuinely nested operations require an explicit parent capability, never automatic same-kind reentrancy. InputModeGate remains filtering, with restoration only while the exact operation owns cleanup.

## Final emission boundary

An outer VM check is insufficient because physical/native preparation can reenter Stop. Add optional `IHostInputOperationAwarePlayer.AttachHostOperation(lease)` for the existing native backend. Exact lease identity protects attachment/detachment; no SDK/player signature is replaced. Add explicit `PlaybackSessionContext.BindHostOperation(lease)` without replacing its existing constructor. Bound input uses the actual context's lease; an unbound old context cannot inherit a different attached operation's authority. Native input rechecks that captured lease after preparation and generic guards, alongside0.45 target/Stop/Pause admission, including zero-input events. Cleanup is permitted only for its exact owner. Real send errors/accepted prefixes retain existing semantics. Windows input remains global and non-atomic; this is not a qualified Roblox background provider.

## Rule18 and Rule20 review

One lock protects rare acquisition/retirement state; hook checks use atomics and no user callbacks under locks. State is bounded to one active/quarantined owner, one actual stop task and one recovery task; no queue or polling timer. One lease/token/completion allocation per operation, no per-event allocations or secret/credential work. Native work stays in the existing executor, and capture remains centralized. Public/SDK/storage formats and IDs remain unchanged. Personal companion references stay conditional; installed Personal/Public/Linux and real accounts are untouched.

Migration is incremental within the existing controllers. Tests must expose current overlap/cleanup failures before relying on the new lease, and integrate shared fake player/picker/arbiter across actual view models (the old MainViewModel fixture used different fake players). Cover simultaneous/reentrant starts, activation ignoring cancellation, pause ownership, Panic during native preparation, failed release/recovery, delayed cleanup/shutdown, stale completion and picker incarnation. Preserve recording accepted tail, save/recovery errors, custom shortcuts, focus restoration and existing document authority. Rollback uses matching development binaries without data migration. No production execution RPC is added before these actual routes share ownership.

Verification uses controlled clocks/services, memory native sinks and isolated sample storage. Root owns one sequential build/test/package lane after source freeze. Source review, simulated positives and real desktop/Roblox evidence remain separate. Full companion/UI/load/competitive/live acceptance stays open.

Independent Rule18/20 review approved this strategy before product edits, with these clarifications: quarantine retains exact cleanup authority; later completion cannot erase a failed retirement; recovery joins an uncooperative callback and has one truthful cancellation/commit point; Drain reports remaining quarantine. Stop-token callbacks are signal-only and must not wait for their own lease completion. Native managed mode remains latched across detached gaps, and cleanup receives the captured lease explicitly through `ReleaseHostOperationInputs(lease)`; stale global cleanup cannot adopt a new attachment. The old MacroController constructor remains, with a new captured-owner overload. Bound picker provenance uses Arbiter.Owns(parent), parent.Kind and CanContinue; only Picker/CaptureTest parents may be explicitly borrowed. Recovery verifies the owning resource kind, never assumes backend key release proves recorder/picker hook exit.

Implementation review also identified F10's independent GDI snip and direct authoring-region prompt. Route them through an explicit tracked CaptureTest helper and the existing shared capture service; the returned frame has explicit caller ownership. Ordinary lease Stop must signal the controller's normal Stop worker, not mislabel every F8 action as Panic. The added normal signal retains tracked completion; direct synchronous disposal from a pending StateChanged signal notification fails clearly instead of joining itself, and outside disposal still cleans managed resources after a signal fault. All lease/controller cancellation callbacks are contractually signal-only: blocking inside a cancellation callback on the same owner's completion/disposal is not supported or claimed safe.

Final cleanup attempts remain independent: an earlier Auto Clicker pause/resume error must not skip the captured native release after the producer and transition tasks end. A successful final release cannot clear the earlier failure; quarantine still requires explicit same-owner recovery. The old stalled-recording fixture must open its controlled consumer gate before joining public Stop, while retaining the existing fault deadline and proving that ownership stays reserved until actual cleanup.

Residual capture migration: `ImageSourceDialog.xaml.cs` still constructs a legacy GDI service and synchronously waits for its one-shot capture. Its modal is now operation-owned, but this cycle does not claim the entire application has one fully asynchronous capture route. Replacing that legacy implementation with the existing injected service is a separately tracked next step under Rules 1, 5, 12 and 20; no latency or native acceptance claim follows from the F10 repair.
