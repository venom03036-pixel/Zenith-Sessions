# Native handoff rejection diagnostics (0.77-live3)

This change makes the first rejecting parser rule visible after a failed native handoff. It does not broaden the accepted grammar or prove that any particular optional field was present in the attended trial.

`NativeHandoffRejectionReason` is a closed enum. Its optional value follows the parser result through the owned browser capture, preparation facts, native provider and configured-provider history into the existing diagnostic text and the allowlisted native-evidence export. No raw URI, arbitrary field name, field value, ticket, credential or exception message is added. The three source examples `referredByPlayerId`, `launchData` and `eventId` receive fixed unsupported-field reasons and remain rejected. All other unknown names receive the generic reason. Earlier count/encoding/context checks retain priority, so the diagnostic identifies the first rejecting check, not a complete inventory of the request.

Existing status enum values, acceptance predicates, guard ordering, timestamp limits, destination/identity checks, single-capture ownership, external-navigation cancellation and dispatch behavior are unchanged. In particular, decoding still occurs before duplicate insertion checks. Accepted candidates have no rejection reason. Typed facts reject undefined reasons or reasons paired with an accepted/missing shape status. Older snapshots with no optional field remain readable, and the evidence format remains version 2 with an additive nullable `RejectionReason` member. The UI change is fixed explanatory text in the existing shape field; layout is unchanged.
