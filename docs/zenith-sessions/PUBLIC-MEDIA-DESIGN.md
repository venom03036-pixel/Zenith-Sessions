# Public media workflow — 0.36 design

Scope: CHAT-22, PROD-UI-01/04, VA-09-02 and PROD-CORE-05. This increment connects real verified-ID headshots and an experience image gallery. It does not complete the all-observed Windows overview or the remaining product gates.

The existing manual headshot presenter, anonymous public directory and strict image checks remain. A single latest-page owner will serialize automatic visible-account requests and manual refresh through that presenter. Its queue contains at most 100 metadata bindings and one pending manual request, deduplicates player IDs, and fences page/profile/grant changes. Hidden pages stop requests; Lock/Panic clears retained media. Runtime startup enables this feature; isolated sample mode and default test composition do not contact public services automatically. No credential reads, per-row workers, new timers or disk avatar cache are introduced.

The optional gallery capability will discover up to ten ordered public image/video descriptors using the public v2 media endpoint and correlate explicit image IDs through the documented thumbnail endpoint. Validate the actual anonymous response before implementing its parser. Descriptors retain requested place and resolved universe separately. Unsupported videos are identified without loading external content. Unknown, pending, moderated and failed images remain explicit; images never establish access, account identity or arrival.

Presentation borrows the directory, owns one cancellable request and at most two frozen 576×324 images (current and prior/adjacent cache). Previous/next is manual; no rotation network loop is required. A context replacement cancels actual work and rejects late publication. Publish operation ownership before observable callbacks so reentrant cancel/disposal can join it. Use the existing directory's two-slot admission, cooldown and encoded-cache budget. Do not add a separate HTTP client for each image or gallery.

Share the current bounded PNG validation implementation behind two fixed entry points: the original exact 150×150 avatar/icon contract and an exact 576×324 gallery contract. Preserve CRC, chunk/order, animation/metadata, exact zlib output/Adler/consumption, full pixel decode and detached frozen BGRA checks. Do not turn the avatar decoder into an arbitrary-size loader. The gallery output is 746,496 bytes per image; two retained images total 1,492,992 bytes, excluding bounded in-flight/encoded and WIC allocations.

Migration is additive, with an optional interface preserving existing providers/mocks and no persisted schema change. Keep current icon/details if optional gallery work fails. Regressions to check: avatar/icon strictness, requested subplaces, stale/reordered/foreign thumbnail IDs, hostile URLs, malformed/oversized images, cancellation/lock/hide during provider/decoder work, reentrant observers, cache bounds, public cooldowns, joined disposal and no automatic requests from sample/test composition. Existing macro, account/vault, queue, input and capture behavior must stay unchanged.

Rollback consists of disabling automatic startup loading and removing optional gallery wiring; existing settings/documents need no migration or recovery. No new dependency is proposed. Rule18: network/decode concurrency, queue count, retained bytes and dimensions are bounded; decoding stays off UI; every request has cancellation/actual shutdown ownership; failures use fixed public descriptions and neutral placeholders. Production renders/keyboard/DPI and real service observations must be reported separately from synthetic tests. This design claims no performance superiority or live-client success.
