# All-observed Windows overview — 0.37 reviewed design

Scope: CHAT-22, CAP-10-01, PROD-UI-04 and PROD-CORE-05. The requested Windows view is a tiled view of observed native clients inside Zenith, separate from arranging native windows. It does not reparent Roblox, forward clicks/input, verify accounts or introduce another capture owner. This additive migration was reviewed by the Core, Windows-provider and presentation reviewers before implementation.

## One capture owner, separate roster

Extend the existing ClientPreviewCoordinator and its same injected provider. Existing selected Start/UpdateTargets remain strict one-to-four, with their current expiry and stop semantics. Add explicit StartOverview/UpdateOverviewTargets for zero-to128 unique valid process identities; HWND0 is a metadata-only unavailable tile and is never captured. The App retains separate observable overview rows, including observed inaccessible/unknown-start/windowless entries that cannot form a capture target. Actual source inventory completeness/revision/time is authoritative; incomplete absence is not exit. Preserve exact PID/start/HWND keys and never invent account association.

Overview updates do not restart stopped/expired work. Unchanged sets preserve cursor; actual identity changes fence/cancel/join the active request and cleanup, retaining only already-validated pictures for exact unchanged identities. An empty roster waits without capture polling. The existing three-second essential-resource lease, pressure, hide, Lock/Panic and actual joined shutdown remain in force.

Add an optional IClientPreviewBatchProvider capability on that same provider: CaptureBatchAsync returns ClientPreviewBatchResult(AttemptedCount,Results), where results are the exact ordered attempted request prefix and requested batches contain at most four. Advance the round-robin cursor by actual attempted prefix length; zero-progress, invalid coverage or exceptions advance one position after normal pacing. An individually impossible target counts as an explicit attempted result so it cannot block others. A time/budget break leaves the tail unvisited. Legacy providers use conservative fallback progress. Never infer a whole four-target visit from a synthetic Deferred tail.

The native overview path keeps one D3D device/readback lane, at most four active sources and the existing192MiB modeled surface budget. Use bounded completed/LRU eviction to admit other windows rather than letting the same first large source permanently win. Dispose borrowed frames/readbacks to actual completion before evicting their sources. Failed cleanup remains owned/quarantined. Preserve monotonic surface checks, native PID/start/HWND and geometry checks, capture indicators and no-desktop fallback. Check a soft inter-target batch time budget; do not abandon an in-flight native operation on a timer. Readback is GPU-reduced: only the smallest mip level that covers the output reaches the CPU (R-instances-8).

## Latest frames, honest freshness and presentation

Only new frames meeting the existing three-second acquisition/future/timestamp validation enter the cache. Overview may retain accepted frames up to120 seconds, appending a Stale output status after three seconds or a deferred refresh, with the original capture time/surface token. Legacy expiry still removes pixels. No stopped, invalid/reused target or unsupported source receives old pixels as a fresh image. Retained Core output is bounded to128×320×180×4=29,491,200 bytes plus at most four incoming detach buffers; frozen App bitmaps have a separate equal bound. Do not retain frame history.

Reuse frozen UI bitmaps when the exact identity/frame token did not change. Coalesce raw inventory and snapshot publication through the current presenter; do not convert every retained frame on every batch or add per-window workers/timers. One completion-paced batch per second allows at most four output frames per second in total; native waits/copies and large windows may lower it. Display actual capture age and measured distinct-frame refresh interval, never a promised per-client FPS.

Add a Windows navigation/button route and a finite equal-cell selection grid with aspect-preserving images, availability/stale overlays and a compact selected-client inspector. All observed tiles remain visible within the operational roster budget; disclose incomplete discovery. Default capture remains opt-in through Start previews. Selection only inspects; explicit Focus uses the existing native identity-checked service. Keep Zenith theme/focus resources, keyboard selection, readable labels/tooltips, and Panic outside the grid. Legacy Table/selected Previews/History routes remain usable.

## Regression, measurement and rollback

Test fair1/4/16/128 rosters,129 rejection, missing windows, partial inventories, invalid/foreign/duplicate coverage, quota/time breaks, zero progress, exceptions, stale timestamps, mode changes, PID/HWND reuse, retained exact keys, expiry, pressure/stop not resuming, ignoring providers, failed cleanup quarantine and actual joined disposal. Test bounded bitmap conversion/reuse, visible tile count, equal geometry, selection/focus pinning and native identity checks with owned diagnostic windows where available. Record source/packaged/controlled-render/native evidence separately; Roblox quality, all-monitor/native focus, sixteen-client load and competitive performance remain unverified until executed.

No dependency, persisted setting/schema, credential, macro or input contract changes are required. Migration is additive by mode and optional capability. Rollback removes the Windows route/overview calls and retains the original selected-preview API/behavior; no data migration is reversed. Rule18 ownership, memory/concurrency/cadence, cancellation, failure visibility, compatibility and testability apply to each layer. The finite128 process-observation budget is explicit and is not a product limit on saved accounts.

The first populated production-view render showed placeholder words beside letterboxed pictures, unwrapped summary text at the minimum width and avoidably small pictures from a mostly empty grid row. The additive correction hides the placeholder once real pixels bind, wraps summaries, and enumerates at most128 candidate column counts to maximize the usable16:9 picture area after the fixed28-DIP caption. Cells remain equal; no text shrinking, new capture owner or stored layout is introduced. A geometry regression and rerun of the exact shipped populated view check cover the correction.
