# Automatic account headshots — 0.36 incremental design

Add one App-owned `PublicAccountPageLoader` borrowing the existing `PublicAccountPresentation`. The loader keeps at most one latest page of100 immutable `(ProfileId, UserId, AuthorizationGeneration)` bindings and one pending explicit manual refresh. It serializes calls to the presenter's single active slot; no row owns a task, timer, HTTP client or decoder. Requests deduplicate by public user ID, while publication remains bound to each profile/grant and the page generation. No credential read, identity reassignment or native account association is introduced.

The reviewed API is `ReplacePage(long pageGeneration, IReadOnlyList<PublicAccountPageBinding>)`, `RefreshAsync(long pageGeneration, PublicAccountPageBinding, CancellationToken)`, `CancelWork()`, `ActiveOperation`, and joined `DisposeAsync`. A bounded async publication callback dispatches to the UI and rechecks page/current row/user/grant, visibility, permission and presenter generation. The actual worker is published before any callback. Replacing/hiding cancels the active request and retains only the newest pending plan; it awaits real completion before using the presenter again. Disposal cancels and joins actual work. Presenter/HTTP ownership stays with Shell.

Shell opts in through trailing `enableAutomaticPublicImages=false`; production App explicitly enables it outside sample mode. Accounts must be visible in a visible, nonminimized manager. The initial visibility is false. Initial readiness schedules the current page only after the library opens. Queries fence old work at entry and schedule only after guarded final publication. Manual Refresh uses the same owner and remains available when automatic loading is disabled. Automatic callbacks never change the global notice. Only verified last-known summary IDs/generations qualify; editable profile IDs/usernames cannot trigger loading. Public names/images stay separate from trusted saved-sign-in labels.

The existing32MiB encoded cache,128 decoded150px entries, strict full PNG validation and public HTTP concurrency/cooldowns are reused. Page hides retain caches; Lock/Panic clear them through the existing Shell owner. Each eligible page pass tries a user once, without retry loops or timer-based recovery. A deferred/failed avatar keeps its placeholder. Profile-success/avatar-unavailable results may remain in the existing presenter's10-minute cache; explicit manual force refresh can retry them. HTTP Retry-After remains fully enforced by the public adapter. This does not claim a strict process-RSS bound or live Roblox compatibility.

Panic suspends automatic headshots until the Accounts context is actually re-entered; explicit Unlock also re-enters that visible context. Late query/authentication reloads cannot silently resume a stopped pass. A cached pending avatar does not block attempts for the rest of a later page pass; a newly deferred provider request ends that pass without retries. The existing gallery receives the same main-window/page visibility fence but starts no automatic gallery network request.

Migration is additive: no saved formats, profiles, credentials, host engine or public API contracts change. Risks are reentrant stop, stale row/grant publication, manual/automatic contention, accidental test network and disposal before native/HTTP completion. Controlled tests cover deduplication, latest-only replacement, manual ownership, cancellation/ignored tokens, dispatcher fences, cache hits and borrowed lifetimes. Shell fixtures explicitly inject fake public directories and opt in; existing tests remain offline by default. Full build/tests and packaged/UI checks remain parent-owned and unexecuted at source freeze.

Rollback removes the loader and hooks, restoring manual-only refresh; existing image caches and stored data need no migration. Rule18: bounded100-row plans, one fetch and one pending manual request, no new capture/input owner, no polling worker/timer or dependency, cancellable bounded HTTP through existing infrastructure, joined actual work and fixed application-owned error descriptions.
