## Change and migration review

The existing queue records an intent and process receipt, but its reservation projection uses the currently saved per-client estimate for every outstanding operation. Lowering that setting can therefore lower a previous unresolved start's forecast. A new candidate is also evaluated using that default rather than its own cost. This increment records a validated physical/commit byte budget on each new request, preserves it through preparation and recovery, and uses it at all admission boundaries. Policy headroom and user limits remain current; per-client estimate edits apply to new requests.

This is an incremental change to the existing serialized scheduler, not a replacement. Queue format 7 writes the optional budget and reads formats 1–6 without inventing their original forecast. An unresolved legacy request without a recorded budget blocks new starts until explicit closure review. Missing/corrupt or unknown-format files remain preserved, and restart never replays work or restores trial consent. A verified format-6 backup remains usable by the corresponding older development build; an older writer must not overwrite a format-7 queue. Installed applications and user data are outside this development increment.

Regression risks include self-double-charging, mixed-cost aggregate-credit correction, stale chosen records after preparation, lost budgets on late receipts or cancellation, old-format fallback hiding newer semantic data, and a lower settings value weakening an existing reservation. Controlled tests will cover these paths, exact byte boundaries, restart and error handling. Source/packaged checks will be identified separately from actual Roblox tests. Rollback uses the preceding staged development build and its pre-format-7 fixture; do not downgrade or rewrite a real updated queue.

Rule 18: work stays on the bounded queue/sample owners; no new timer/thread, credential access, native input, client mutation, dependency or unbounded history. Costs are finite, nonzero, bounded byte quantities. Cancellation and failed persistence retain existing ownership. Projection work stays bounded by the existing queue/inventory limits. This closes a reservation correctness gap; workload peak learning and measured sustainable capacity remain separate unfinished requirements.

## Implemented paths

- `LaunchResourceBudget` stores positive exact physical/commit byte quantities, each at most 1,024 GiB. `FromSettings` rounds upward once. New queue operations pin that snapshot before mutation/persistence; invalid or failed resolvers cannot start or commit a request or disclose arbitrary exception text.
- The serialized owner uses the current candidate record at preflight, after authorization/preparation and at the prepared native boundary. It excludes only that un-emitted candidate's forecast, preserving every other one. Prepared intent adoption, cancellation, late receipts and restart retain the budget. A legacy possible client cannot gain a known forecast from an exact process observation.
- Projection credits only coherent exact-instance private consumption already included in the system sample. Mixed budgets restore their own original full cost when aggregate credits conflict. Missing legacy budgets retain explicitly provisional display arithmetic but set `ForecastsKnown=false`, denying new admission until explicit closure review. A closure marker never hides Windows occupancy.
- Each candidate is divided by its own byte cost with current spare margins, remaining reservations and user limit. The pressure latch instead observes raw spare-memory/commit health, critical exhaustion, sustained CPU/GPU and recovery; it is not latched by a different default estimate, the current candidate's own reservation or a client-count limit. These checks remain separate and both are required.
- Source review identified a separate-field desktop/health publication race. A single immutable published pair now drives admission; presentation updates cannot combine a newer sample with older healthy permission. The deterministic Shell test validates this contract with a critical sample that would otherwise fit under explicitly permissive spare settings. The original runtime interleaving was not reproduced.
- Queue format 7 reads 1–6 without inventing their budgets. Raw preflight detects nonnull newer budget markers hidden in old formats/duplicate JSON before fallback. Unknown future primary or backup generations are preserved. Known malformed current data may use the verified backup. Older pre-start/review/receipt semantics stay conservative; restart does not replay or restore trial consent.
- Queue rows expose the pinned estimate with a full tooltip. Settings and Guide explain that per-client default edits affect new requests. Overview gives after-headroom available physical/commit bytes versus the candidate cost, and suppresses an optimistic slot estimate when original forecasts are unknown.
