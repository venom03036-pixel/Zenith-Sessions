## Implemented behavior

Saved profiles, observed processes and queued requests now precede compact resource histories. Accounts, Windows, Automation and view-only Open queue navigation remain nearby. Detailed admission, reservation, pressure, performance and GPU explanations are retained in a collapsed expander. Existing chart objects and the bounded recent-activity source remain in use; navigation does not start capture, resume the queue or launch a client.

One immutable App projection publishes full-library totals with their successful-load date, independently dated process scans, all-operation queue summaries and original resource/forecast times. Unknown/opening/faulted values stay unknown. Partial, stale, future, duplicated or invalid process rows cannot become a complete total; valid windowless processes remain countable. Fresh memory cannot renew an old process scan. CPU requires a valid finite reading, and a stopped monitor stays explicitly stopped after a manual refresh. These are display facts, never account, arrival, input or admission authority. No new poller, query, media loader, capture owner or dependency was added.

Review found that an old waiting Resume could overwrite a newer Panic after acquiring the queue serial owner. Core now pins its stop generation before waiting, rejects superseded resumes, rechecks immediately after writing the resumed state and reports an explicit acceptance result. The existing SetPausedAsync signature remains compatible. The App clears its pause latch only for an accepted, still-current explicit resume; old UI callbacks cannot relabel a stopped queue Active. Successful Pause updates its next-toggle intent immediately. No queue schema, provider, credential or macro format changed. The [reviewed design](OVERVIEW-WORKSPACE-DESIGN.md) records scope, regression risks and rollback.
