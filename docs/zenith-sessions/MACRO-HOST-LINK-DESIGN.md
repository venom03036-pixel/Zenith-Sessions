# Personal macro-host catalog link — 0.34 design

This incremental integration connects Sessions to the actual Personal editor's saved macro metadata. It is a prerequisite for shared assignments, not a background execution provider. Existing MacroSuite input/foreground/capture checks remain unchanged; no Run command, decrypted macro body, image template or credential crosses this first protocol. The existing RESTORE pipe is separate. No installed application is replaced or user library opened by tests.

## Components and contract

- Add a small .NET8 `Zenith.MacroHost.Contracts` domain project and `.NET8-windows` `Zenith.MacroHost.Windows` pipe implementation. Both the current .NET8 Personal host and .NET10 companion can reference these existing-platform-only libraries; no NuGet dependency is needed. Sessions.Core remains platform-independent. Personal host project references and integration files are conditioned on DeveloperMode; Public output gains no companion endpoint or new runtime dependency.
- Contracts namespace `Zenith.MacroHost.Contracts`: `MacroCatalogQuery(int Offset=0,int Limit=100,Guid? HostSessionId=null,long? CatalogRevision=null)`; `SavedMacroDescriptor(Guid Id,Guid SavedRevision,string Name,string Hotkey,int TopLevelActions,bool Enabled,string TargetMode)`; `MacroCatalogState` = Ready, Starting, Changed, Unavailable, Incompatible, Disconnected, Busy; `MacroCatalogPage` carries state, immutable host-session ID, catalog revision, host version, bounded entries, total, nullable next offset and a static explanation. `IMacroCatalogSource.GetPageAsync(query,ct)` and `IZenithMacroCatalogClient.GetPageAsync(query,ct)` return that page. Background execution is always unavailable in this protocol.
- `SavedMacroCatalog` is a bounded thread-safe publisher/source. Upsert only after a successful encrypted save or a successfully loaded/imported saved model, with a new opaque SavedRevision token. Tokens are scoped to HostSessionId, not persistent content hashes. Reset/load/remove updates catalog revision. Dirty drafts and failed saves do not replace a saved descriptor. Names are bounded display metadata, never executable paths or launch instructions. Missing/damaged library information is explicit, not an apparently empty healthy library.
- Personal editor integration uses partial hooks for successful saved/loaded publication and library lifecycle; public builds compile out those calls. On removal, stop exposing that macro without retaining an unbounded deleted-descriptor history. An immutable sorted metadata copy is created on explicit page requests outside UI work; requested generation changes produce Changed, not mixed pages. No macro serialization/hash, document decryption, file scan, capture or input is added to UI updates or telemetry refreshes.
- Wire protocol version1/product `Zenith.Macros.Personal`: one request/response per connection, matching nonempty request ID, only the Catalog operation. Strict bounded JSON, four-byte length prefix, <=256KiB per frame, <=100 entries/page and <=10,000 entries/snapshot operational metadata budget. Unknown versions/operations/members, malformed UTF8/JSON, duplicate/mismatched IDs, invalid cursors/entries and impossible page shapes are rejected. A response cannot advertise background automation.
- Named pipe `Zenith.Macros.Personal.Catalog.v1` uses asynchronous CurrentUserOnly streams and server FirstPipeInstance. One owned accept/handler loop, one active request, bounded IO deadlines, explicit stop and joined disposal; do not abandon work on observation timeout. Scope is one current Windows user, not protection against malware already controlling that user. No network listener, privileged rights, installation discovery, browser or arbitrary executable launch.
- Sessions displays an explicit Refresh host macros command and paged saved-macro rows on Automation. It reports absent/incompatible/busy/changed/unavailable host distinctly and preserves the last received rows as stale on failure. Metadata connection is not proof of account binding or input capability. Macro execution/broadcast stays unavailable, without success-looking Run controls. No automatic host launch, polling loop or hidden library access.

## Risks, migration, rollback and tests

No stored schema or macro document is changed. Conditional project references, partial editor hooks and one optional personal composition endpoint are additive. Main risks are misreporting drafts as saved, stale page mixing, UI/pipe deadlock on shutdown, unbounded frame reads, malformed peer data, endpoint collision and exposing the endpoint in Public. Tests must cover actual successful/failed saves and load/delete/import paths, generation conflicts, bounds/cancellation, interrupted frames, current-user pipe round trips, absent host and joined shutdown; Public build/dependency exclusion and existing Personal regressions must be checked. UI checks use isolated sample data and an owned metadata host, not real macros/accounts. Exact final binaries must be verified. Rollback removes the conditional endpoint/client page; preferences and encrypted documents are untouched.

Rule18: explicit page/frame/catalog/concurrency bounds; no per-profile worker, timer, capture loop or new external package; calls are cancellable and owned. Metadata publisher failures must not turn an already successful document save into a reported save failure. Actual macro dispatch, selected-target ownership, host-wide input arbitration, capture integration, real Roblox support and live acceptance remain subsequent work.
