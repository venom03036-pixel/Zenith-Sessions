# Final input admission and host ownership prerequisites

Cycle0.45. Previous0.44 made concrete progress: exact saved-byte authority, integrated protected-store/editor/interpreter memory-input evidence and independently checked final artifacts. The full product goal remains active. This increment repairs the already identified final foreground check before adding any production execution RPC. It does not qualify background input, accounts, native arrival or reconnect.

## Observed gap and bounded repair

PlaybackSessionContext inspects a pinned target before calling its sink. Win32InputPlayer then reads cursor/physical state and calls the generic cached foreground guard; its final SendChecked does not freshly check the pinned target. A callback/focus change in that interval can therefore pass earlier checks. A fresh check immediately before native submission narrows this race. Windows SendInput still has no target parameter or atomic foreground reservation; do not claim atomic delivery or receiver consumption.

Add an optional context-aware sink capability, preserving IInputPlayer, existing sink signatures and the SDK. The session passes **itself** when dispatching ordinary events, restoration and cleanup to capable sinks. Do not derive authority from `_sessionOptions.Session`, which can retain a different prior operation. Old sinks retain their adapter path.

Keep one immutable PlaybackOptions snapshot per PlaybackSessionContext, configured by the existing PlaybackSessionRunner before events. The context-aware native path uses that owner's snapshot for translation/tags; no per-session dictionary, AsyncLocal authority, unbounded task or new input owner is introduced. A strict pinned target must not translate through a different nonzero options window handle. Direct session events without configured options retain the default InputEvent screen-coordinate semantics; they must never inherit another session's mapping. Legacy no-session playback remains unchanged.

Review clarification: refresh this snapshot **per playback batch**, not only once per macro; click/move/key steps legitimately provide different mapping fields. Configure under the existing emission lane and copy immutable scalars with Session=null. Reject a contradictory strict nonzero window as a fixed configuration error, rather than a focus-pause loop. Prepare fresh virtual-desktop metrics for direct absolute events before final admission so a newly used player cannot normalize through zero or another context's old metrics. Suppressed absolute moves still require final zero-input admission before being consumed.

Provide a synchronous, side-effect-free admission helper: check caller cancellation and actual controller Stop/Panic/Pause, freshly inspect the resolved target through its existing domain service, then check stop/pause again after the query. Explicit targets without usable verification fail closed. Keep legacy null-target and Screen switching semantics. Return/throw a fixed typed deferred outcome for manual pause/target unavailability, distinct from genuine native failure. Never call Pause, TargetPaused or controller/UI callbacks while the native held-state lock is held.

Native order is preparation/physical probes and filtering, generic foreground guard, fresh owner target+stop/pause check, then native submission. Check even a fully filtered zero-input event before reporting it complete. Stage borrowed-key additions/removals in bounded reusable scratch sets; apply only after admission. A denied Down must not leave a borrowed marker that suppresses its later retry, and a denied Up must not erase an existing marker. Physical ownership still advances only for the actual accepted native prefix. Cleanup remains available regardless of focus, pause or stop; it sends only owned releases.

EmitAsync handles deferred admission after unwinding native and emission locks: publish a tracked manual pause, retain the unsent event and desired holds, and retry only after deliberate resume. RestoreAfterAsync treats expected deferred/stop outcomes as a completed transition rather than poisoning `_transition`; any successfully restored prefix remains tracked and is released by the subsequent pause. A later manual resume restores unfinished holds once. Preserve genuine native failures, but ensure an earlier failed transition cannot prevent Stop/Dispose attempting cleanup of already-confirmed holds. Do not falsely report successful disposal if cleanup failed.

Publish pause/transition handles before callbacks can reenter. Avoid a release transition awaiting the restore that is awaiting that same release. Keep cancellation, subscription disposal and failure outcomes observable. Review sink ownership/option snapshots, reentrant callbacks and partial restoration before freezing source.

## Rule18 and Rule20 review

This is an incremental repair to existing Core/Windows paths, not a new executor or replacement interpreter. It adds no packages, timers, per-account workers, credentials, capture loop or native API. Core remains WPF/Win32 independent. One options reference per live session and reused bounded native-filter scratch are permitted; no cloning a held set per input. Fresh target inspection adds work per ordinary emission; record the extra query count and do not claim a performance improvement without real measurements.

Compatibility risks are session attachment versus explicit options, pointer translation, borrowed physical keys, pause/restore ordering, cleanup after failure, and legacy Screen/no-session playback. Keep stored formats, IDs, shortcuts, document authority and public assembly contracts intact. The Personal-host integration stays conditional. Rollback restores matching development binaries without rewriting data; no installed Personal/Public/Linux edition or real session is changed.

Verification uses memory-only native sinks and domain-service fakes. First reproduce the late-focus/borrowed-state failures against unchanged source, then run corrected cases, Core regressions, affected existing native-player tests and the manager/package suite. Cover keys, Unicode, relative/absolute pointer, clicks and wheels; focus/PID incarnation changes; pause/Stop/Panic/cancellation during probes and Inspect; fully filtered borrowed events; stale old options versus a new context; partial restoration and genuine native failure; cleanup with unsafe focus; reentrant callbacks; and no replay after explicit resume. Native/desktop acceptance remains separate. No real Roblox input is authorized at this stage.

## Separate host ownership audit

App currently shares one player between editor and Auto Clicker, but UI booleans are not atomic leases. PlayAsync locks a batch while direct click/move paths bypass that lock. InputModeGate is a mode/filter, not an arbiter. Session attachment assumes external exclusivity. Auto Clicker catches release failure and clears activity flags even though the player retains unaccepted holds. These are source findings, not claimed live reproductions.

Before execution RPC, add one app-composed, typed nonqueued operation arbiter. Acquire before asynchronous startup; retain through pause, actual completion and cleanup. Failed cleanup quarantines admission until explicit recovery succeeds. Recording and pickers participate without replacing InputModeGate's filtering purpose. Future targeted groups reserve against legacy desktop activity while the existing targeted owner leases individual recipients; never attach independent background runs to the shared Win32 player. Shutdown must join actual owners, and stale picker/session cleanup must not stop a replacement. This audit remains a prerequisite, not a claim that the arbiter exists in0.45.
