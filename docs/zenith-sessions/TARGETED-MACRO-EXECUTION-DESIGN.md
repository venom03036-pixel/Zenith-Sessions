# Targeted macro execution integration

Cycle0.43, November6,2026. This advances the mandatory execution investigation by connecting the **real MacroSuite.Core interpreter** to the existing per-target input owner, then exercising the chain against registered cooperating windows. It does not replace the required Roblox/background/image/account/arrival work with a foreground or simulated result. No live Roblox qualification or finished release is claimed.

## Architecture and migration

Extract the unchanged pure targeted-input types/coordinator and PixelRectangle into one small first-party `Zenith.Automation.Input` library targeting.NET8. Keep their existing full type names and provide type forwards from Sessions.Core so older compiled companion callers remain resolvable. Sessions.Core references the new assembly; no duplicate input owner or transport implementation is introduced. Preserve serialized values/signatures. The.NET8 runtime permits the existing Personal host and.NET10 companion/probe to reuse the same source later, without per-input IPC. Public product projects and installed editions are not changed.

Add a separate.NET8 `Zenith.MacroHost.Execution` library referencing the existing MacroSuite.Core interpreter and shared input owner. It owns a bounded set of explicitly eligible run leases. One privately frozen compatible plan may supply independent MacroExecutor, MacroContext, controller, active-time clock, target, holds, progress and cancellation for each run. Never share mutable MacroStep/model instances between executions; copy supported source fields into bounded immutable plan data, then construct private steps for each execution. Do not recreate the interpreter. An explicit immutable input-support declaration lists permitted keys/signal kinds; check the complete frozen plan against it before opening a lease, so a later unsupported action cannot follow earlier emitted input.

Admit only deliberately selected registered recipients/purposes supported by the injected transport/eligibility policy. The shipped transport remains restricted to the existing NativeProbe's own registered process/windows. An ownership lease is not account or input authority. No generic Win32 fallback, foreground activation/cycling, external process registration or Roblox eligibility upgrade is added. Catalog v1 and assignment storage remain reference-only. Do not expose an executable Run button or incomplete control RPC yet.

Existing ClickStep/MouseMoveStep need a recipient for their explicit client-relative path. Add one optional first-party IClientRelativePlaybackTarget capability exposing an explicit handle on the player. It supplies geometry-routing metadata only, never foreground/account/input authority. Two recipient-selection expressions may consult it only when the existing resolved playback target is absent; old players do not implement it, so their prior window-coordinate paths stay intact. Keep IInputPlayer/SDK signatures unchanged. The bridge rejects nonempty saved window-name hints and never fabricates an active/foreground observation or clears a saved target rule. Root approved this small additive seam before implementation; existing Core click/move/executor regressions are required.

The extracted coordinator exposes one additive read-only `MaximumHoldsPerRun` value. Whole-plan admission compares its peak logical holds with the actual owner limit as well as the declared transport vocabulary; an overstated transport declaration cannot let an earlier input run before the owner rejects a later hold. Existing constructor, type names, signatures and numeric states remain compatible.

## Supported plan and input semantics

Validate the entire source before opening an input lease or emitting anything. Initial executable actions are the existing explicit virtual-key strokes, delays, client-relative clicks/moves and vertical wheel, subject to declared action/coordinate support. Reject unknown/custom types, Unicode, mouse-camera/relative-delta movement, screen-coordinate positional actions, desktop/image/color/AI/plugin paths and unsupported control-flow blocks before execution. Reject incompatible saved target policies rather than clearing/rewriting them. Diagnostic fixture macros must explicitly opt into their unbound owned-window diagnostic scope; a legacy or screen recording never becomes a production per-window macro by assumption. Record these remaining features as unfinished, not accepted parity.

Preserve event order, recorded timing, speed and supported coordinate semantics. Validate finite repeat/action/runtime/speed budgets and reject RepeatUntilStopped in this initial bridge: the interpreter deliberately skips its usual runtime/iteration ceiling in that mode, so supplying MaxRuntime alone is not a bound. This leaves indefinite user macros unfinished rather than silently changing them. Verify exact HWND/process-start/registration/geometry at the existing final targeted emission boundary. Size scaling requires an explicit compatible recorded client size; never use a preview image as macro capture. Each next unsent event waits for pause/resume; completed events do not replay. Arrow keys remain ordinary keys; no camera API is introduced.

The legacy interpreter calls synchronous ReleaseAllHeldKeys at control-flow and terminal boundaries. Add an owned async **clear holds while retaining target lease** transition to the shared input controller. Clearing removes logical and submitted holds; it is distinct from Pause, whose unfinished holds can restore. Preserve an existing/arriving Pause: clear drops its logical restore intent, stays paused, and later Resume cannot restore cleared holds. Clearing during restoration fences that restoration and finishes paused. Append a Clearing run state without renumbering old values; repeated clears share their owned transition. Stop/Panic/fault always wins, cleanup failures quarantine the lease, and a later run cannot reuse it prematurely. A fault is a cleanup failure only while the input run still owns submitted holds: when every release was queued (for example, after the window moved or resized) or the recipient is definitively gone, the macro reports an input fault, stops its input normally and frees the lease. The adapter's synchronous entry only requests/tracks that transition; subsequent emission and finalization await its actual completion. Never fire-and-forget or block the UI.

One run composition owns controller/target pause ordering and tracked transitions. Close emission before async pause cleanup, restore only unfinished holds after explicit resume/revalidation, and keep control/active-time waiting aligned through PlaybackSessionContext or an equivalently reviewed active-time hook. Do not rely on DelayStep's legacy coarse no-session delay as pause-accuracy evidence. Dispose joins the actual interpreter, pending clear/transitions and final release; inspect both interpreter outcome and target cleanup rather than treating successful Task completion as clean termination. Exceptions become fixed bounded outcomes; no macro contents, labels, secrets or raw exception text enter diagnostics. Repeated Stop/Panic/dispose share owned work.

Test shared library compatibility on.NET8 and.NET10, including a pre-extraction compiled caller resolving the forwarded public types. Existing foreground players and catalog/assignment behavior must retain their regressions.

Extend the existing NativeProbe (no new capture owner) to invoke the real interpreter through this bridge for two registered cooperating receivers, with one unrelated/cover window, receiver acknowledgments, independent progress, pause/resume and Stop/Panic. Preserve existing source/result labels and never classify these windows as Roblox. Any native test unable to run remains explicitly unverified. Final source/staged regressions, packaged runtime dependency checks and exact native-probe identity must be recorded.

Rule18: bounded plans/runs/batches/holds, no credential or HTTP access, no per-account browser/timer, one controlled target-input owner, explicit tracked cancellation/cleanup, no new external packages. Rule20: incremental extraction with type forwards, additive clear transition and isolated execution library; rollback removes the bridge and restores source placement without changing stored macros/settings/queues. Root and the independent reviewer approved the design and the explicit finite/clear/pause constraints before edits.
