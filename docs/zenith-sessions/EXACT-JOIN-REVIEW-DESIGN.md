# Exact join review and session destination handoff

The 0.47 work is verified progress. This cycle repairs the routes from Accounts and Sessions into Join a game, and the handoff from the destination review to the existing selected-account native trial.

- Accounts opens Join a game for a selected profile with or without a preferred place. Keep the current requested destination and text draft. The explicit preferred-game command keeps its separate behavior.
- Sessions offers a direct way to review a currently reported destination. Share the final freshness gate with Copy reported server link. Require a fresh complete local process inventory, an exact unique PID and start, and a single applicable current log diagnostic with a valid lease. Refuse missing, ambiguous, reused, stale and last-known inputs. The latest holder observation must still be fresh. A reported place or job event retains the existing five-minute fact lifetime while that same stream remains corroborated (since 2026-11-08 the Sessions row keeps showing the place and server past that lifetime with a "last confirmed N min ago" marker while the log still says Connected, but Review reported server and Copy refuse them as last-known). Preserve the full place ID and job GUID as an unverified request draft. Search / Use remains explicit. The account and queue remain separate.
- Put the selected-account trial next to the destination, ahead of server browsing and queue details. The review captures the exact saved profile revision, expected signed-in UserId and authorization generation, resolved PlaceId and JobId, selected installation, and existing stop epoch. Use only that review after the modal returns. Recheck current selection and lifetime and consume the review once. A different account, grant, destination, installation or stop requires another review. When the account or destination changes while a confirmed start is still checking Roblox's release or the saved sign-in (up to five seconds), that start is cancelled and the trial card says "Trial not started: the selected account or destination changed while it was being checked"; Stop trial, an installation change, Panic and Lock keep their own stop reason instead. Stop trial is the queue's Panic signal, so it pauses every queued request, not only the trial: the checking line says "Choose Stop trial to cancel it; that also pauses the launch queue", and the stopped card says the queue is paused and names Resume queue. No parameterless command route should begin a trial. Keep normal queue eligibility and native-provider classification unchanged.

Roblox documents the legacy place and game-instance parameters and recommends share links for new links. [Roblox deep-link documentation](https://create.roblox.com/docs/production/promotion/deeplinks) A local diagnostic job ID can prefill the app's existing exact-request parser. The scope grants no new private or reserved-server access and no action authority from log content.

Rule 18. Bounded click-time inventory and diagnostic checks use the existing shared snapshots and leases. The UI stores at most one transient trial review. Synthetic fixtures can check the full local path through pinned request and prepared start. Live account binding and arrival still need independent observation.

Existing request parsing, checked and bundle recipients, provider fences, and privacy-sensitive paths stay in use. Regression checks cover account navigation without a preference, latest destination evidence and rejected changes while the confirmation is open.
